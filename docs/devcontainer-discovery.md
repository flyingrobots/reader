# GitHub devcontainer discovery

`reader_mcp.devcontainer_discovery.discover(github, repo, ref)` provides read-only configuration discovery without a local repository checkout. It resolves a branch, tag or commit reference once, then reads immutable Git trees through the GitHub adapter. Its result binds the repository, requested reference, base commit and every configuration’s Git blob identity.

The supported discovery locations are `.devcontainer.json`, `.devcontainer/devcontainer.json` and `.devcontainer/<name>/devcontainer.json`. Multiple choices remain distinct; discovery does not silently choose one. Only regular configuration blobs and ordinary tree directories are accepted. Executable-bit regular blobs are still files; symlinks are refused. Named directories are inspected in sorted order.

A `missing` result with `requires_inference_consent: true` means the complete supported inventory contained no configuration. It is a requirement to obtain the operator’s consent, not consent itself. Authentication failures, API failures, missing revision/tree identities, truncated inventories, duplicate or ambiguous paths and unsupported symlink locations raise errors. They never become evidence of absence. Each tree is limited to 4,096 entries and discovery permits at most 64 named directories; reaching either limit stops discovery rather than truncating the result.

This helper is a foundation for the container runner. Its authenticated preview API does not register repositories or start jobs. The default Coding Jobs runner requires a container approval and refuses legacy host-checkout execution. Discovery does not parse or execute configuration commands, download source files, build images, transfer credentials, start coding agents or approve an inferred configuration. Runtime readiness, configuration validation, consent storage, resource supervision and durable recovery are separate responsibilities.

GitHub access uses the existing `GhCli` adapter and its configured authentication. The added `revision` and `tree` operations are fixed GET routes; the reference is encoded as one URL component. A valid response must contain full Git object identities. For a discovery failure, restore GitHub access or correct the configuration/inventory issue and repeat the read; do not substitute a guessed configuration for a failed read.

Synthetic tests in `tests/test_devcontainer_discovery.py` exercise complete absence, multiple configuration choices, immutable follow-up reads, API/authentication failures, malformed or incomplete trees, symlinks, directory limits and URL encoding. Run them with `tests/test_github.py` in the bounded Docker validation environment. These tests establish the read-only discovery contract; they do not validate container execution or agent authentication.

## Configuration preview

`select(github, repo, revision, path)` in `reader_mcp.devcontainer_config` repeats discovery at a full immutable commit identity, then reads the selected Git blob by its identity. It checks the blob’s declared size, base64 encoding, Git blob hash and content length before parsing. The source is limited to 64 KiB. The preview retains the commit, path, Git blob identity, source SHA-256 and normalized configuration; it does not imply consent, image readiness or registration.

The parser accepts UTF-8 JSON, a UTF-8 BOM, line/block comments and trailing commas. Comment-like text and commas inside quoted strings are preserved. The managed-runtime validator currently supports an image, ordinary environment maps, root inside the container, lifecycle commands, `waitFor` and editor metadata. It refuses Dockerfile/Compose/Features builds, host initialization, mounts, resource overrides, custom workspace paths, environment interpolation and overrides of managed authentication/cache/temp paths. Unsupported fields produce a named refusal instead of being silently dropped.

Authenticated local callers can use POST `/api/repositories` with `{"action":"discover-container","repo":"owner/name","base":"main"}` or `{"action":"select-container","repo":"owner/name","revision":"<full commit SHA>","path":".devcontainer/devcontainer.json"}`. These actions require the existing local requester and token checks. They neither modify the repository registry nor admit a job. A GitHub inspection error is an error response without an absence/consent result. The Repositories Admin form uses these actions before allowing registration and invalidates a preview when repository or base changes. Missing configurations require a separate consent checkbox and Infer action; discovery alone never grants consent.

## Explicit inference

Local callers may submit `{"action":"infer-container","repo":"owner/name","revision":"<full commit SHA>","consent":true}` after a successful missing-configuration inventory. Consent is checked before any GitHub request. Reader repeats the inventory at that immutable commit and refuses inference if a supported configuration exists. It inspects root Node/Python manifest names and proposes the managed `reader-coding:local` image only when one of those toolchains is represented. The response includes manifest evidence, assumptions, the normalized configuration and its canonical SHA-256. It does not install project dependencies, approve compatibility, prepare an image or register a repository. A failed inventory never becomes an inference proposal.
