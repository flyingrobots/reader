# Container configuration and supervision foundation

The active Coding Jobs migration now includes authenticated local API actions for immutable GitHub discovery and configuration preview. Preview verifies Git blob identity and size, parses JSONC and refuses unsupported host initialization, mounts, builds/features, interpolation and resource overrides. Neither action registers a repository or admits a coding job. API failures remain errors instead of inference consent.

Added a persistent-volume runtime helper with owner/repository labels, a canonical workstation resource lease, immutable image identity checking, recorded creation intent and container identity, actual tmpfs capacity inspection, control-plane process deadlines/output limits, container stop confirmation and volume-preserving teardown. Workspace and host-control accounting include open unlinked files. A concrete regression demonstrated a retained mapped file after every descriptor closed: the old measurement reported only 40 bytes while the backing file retained 1 MiB. The corrected helper accounts for the inode when possible and otherwise refuses measurement; it does not claim complete measurement when kernel access is unavailable.

Validation ran only in the reused bounded Docker worker. The final focused foundation/API suite passed 79 checks in 11.03 seconds. The subsequently added live-monitor-failure scenario passed with all 8 runtime unit cases in 0.83 seconds. Real Linux process tests cover closed output pipes, combined output limits, cleanup after leader exit, unlinked descriptor storage and retained mappings. Runtime Docker interactions are fakes, and macOS descriptor parsing uses synthetic records; these are explicitly not real daemon/CLI/authentication/end-to-end job evidence.

Two early runs were fixture errors: the small validation tmpfs correctly failed the production 50 GiB host-floor check until the unit fixture supplied a synthetic host measurement; the HTTP fixture already starts its idle queue worker, so a test was corrected to assert unchanged worker identity and run inventory. Neither error is product-regression RED. The retained-mapping assertion is meaningful RED, followed by GREEN accurate-accounting-or-refusal behavior.

End measurements before removing the owned worker were approximately 313 MiB workspace, 5.4 MiB temporary data and 15 KiB host phase logs. Host and Docker backing free space both exceeded 50 GiB. The worker was removed and its shared-resource lease released. No production coding volume, new runtime image, credential transfer or live coding agent was created.

The production runner and Admin registration form remain on the existing host-checkout path. Remaining work is the container job adapter, configuration/inference consent persistence, managed image/tool preparation, independent container authentication, cancellation/restart reconciliation, Admin controls and real bounded Docker integration through the complete synthetic job flow. The full migration goal remains active.
