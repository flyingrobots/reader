# Changelog

## Unreleased

- The Scratch pad's Save dialog is a shadcn form (Field, Input, NativeSelect, Notice) in a Dialog; Reader has no native `<dialog>` left, and the `dialog` element CSS is removed.
- The Documents picker is a shadcn Dialog that keeps its plain-JavaScript content mounted. Focus leaves every app dialog as soon as it starts closing, as it did from a native dialog, and returns to the document when nothing else had it.
- The annotation dialog (Textarea and Button) and the Speak menu (a vertical ButtonGroup with Kbd) are shadcn Dialogs; their native `<dialog>` elements and CSS are removed. Each dialog's first control takes focus as it mounts, so keys typed at once reach it.
- Keyboard help and the diagram viewer are shadcn Dialogs (`openShellDialog`), replacing native `<dialog>` elements. `modalOpen()` in `web_ui/modal.mjs` replaces seven `dialog[open]` checks and counts both kinds.
- The versions timeline is built from shadcn components: Badges for its tags, a Collapsible for each edition's history, Kbd hints and Buttons. `timelineModel` replaces the HTML string; the keyboard model and comparisons are unchanged.
- Link previews are a shadcn HoverCard anchored to the link (a bottom sheet on phones). `links.mjs` still decides when they show; the HTML string and its CSS are gone. Two Linked from order checks in web_links now allow the learning card beside them.
- On phones the status line keeps the version chip, which says which edition you are reading, and lets the outline button and then the layout switch give way first. The chip had disappeared at 390 px since the quick theme picker joined the always-shown items. The priority table in docs/web.md lists the current ranks.
- The reading log under a document's title is a shadcn component: a Collapsible line and Item rows, with the folded task agents in a nested Collapsible. `readingLogModel` replaces the HTML string builder, and its legacy CSS is removed.
- The Library's gallery charts moved into TypeScript. Their data helpers are in `gallery-model.ts` (still unit-tested from Node), the calendar and reading-by-topic charts are in `library-charts.ts`, and the shelves are a React component with a shadcn Breadcrumb and NativeSelect. `web_ui/library-charts.mjs`, the chart callbacks `app.mjs` passed to the page, the unused atlas and their legacy CSS are removed.
- `scripts/stray_work.py` reports finished work that has not reached `origin/main`: unpushed or unmerged branches, squash-landed branches that are safe to delete, and clean, merged worktrees that can be removed. It never deletes anything. See docs/stray-work.md.
- The Reader service follows `origin/main` by default and fetches it before each install and update, so the preview shows what was pushed. Fetches take the repo `.git/` lock; offline, the updater keeps the last fetched commit and logs `fetch-failed`. Previously it followed the local `preview/integration` branch and never fetched.
- The committed web bundle is checked against its sources: `tests/test_controls_bundle.py` fails on a forgotten rebuild, a hand-edited output or a leftover chunk, using the hashes `build-meta.json` already records. `.gitattributes` marks `controls/` as generated, with a `reader-bundle` merge driver that keeps one side for a rebuild instead of writing conflict markers (see docs/web.md).
- Three browser suites pass again on main: the help and command-line tests follow `:themes` and display labels, Read next is checked by order, and palette-only themes may use one mode color.
- The shadcn sweep continues past Admin:
  - Search uses InputGroup, ToggleGroup, FieldSet facets and Item passages.
  - The reading queue uses Item rows in its listbox, Progress, ToggleGroup and Kbd.
  - The Theme Editor uses InputGroup token rows, a Slider, ToggleGroups, Collapsible checks and one AlertDialog in place of `window.confirm`.
  - Chat uses Markers for system notes, Notices, a Card for the raised hand, and a Collapsible and ToggleGroup raw output.
  - The article prompt card is a Card with a shared JobSummary.
  - The quiz, writing prompt and What changed use Notices, LoadingState, Collapsible, Items and Badges.
  - The vanilla bridge gives Reader's plain-JavaScript chrome real Kbd classes, and close buttons use lucide's X icon.
  - `tests/web_page_review.cjs` reviews these pages, and `docs/ui-design/` holds their sheets and an audit of the remaining native dialogs and panels (follow-up #200).

Totals and works are Items, each chart is a StatusCard with a Button legend, and the D3 drawing moves to `library-charts.ts`. Selection, Shift-click split opening, chart keyboard access and the high-contrast chart outlines are unchanged. The dashboard's dead CSS leaves `style.css`.

- Article prompts that become coding jobs (RW-44): an article's `<!-- reader:prompt {…} -->` wrapper around one `text` fence (plain, copyable Markdown everywhere else) shows as a prompt card with the repository, issue, an editor, **Copy**, the coding agent (Codex or Claude Code), **Run → PR**, **Stop** and earlier runs. Nothing runs on view. The browser (`web_ui/prompt-blocks.mjs`) and the server (`prompt_blocks.py`, markdown-it-py with Reader's math rule; new dependency `markdown-it-py` 4) read the same markdown-it block tokens with the stated bounds, and a 700-document generated corpus pins their agreement; forged HTML, examples inside fences, duplicates, malformed or unknown metadata stay ordinary code. **Run → PR** admits a run by request UUID (idempotent; different input under the same UUID is a 409) after re-reading the article's SHA-256, then a new server-owned repository-job runner (separate from the chat runner) checks the repository registry, GitHub access and the issue, creates a worktree on `reader/<id>-<run>` from the pinned base, runs the agent there, links or creates the issue, runs the registry's guarded verification, pushes normally and opens a pull request that is read back before the outcome is `pr_opened`. Outcomes `pr_opened`, `already_fixed`, `blocked`, `failed`, `cancelled`, `interrupted` and `needs_reconciliation`; lost GitHub acknowledgements are reconciled by marker or branch, never repeated; a restart reconciles instead of relaunching. The server-local registry (`.reader/repositories.json`, `GET/POST /api/repositories`, registration from this Mac only) maps `owner/name` to a checkout, remote, base, worktree folder, agents and verification command. Every run is archived forever under the new `coding-job` LLM log kind with its request, prompts, CLI output, verification output and sequenced events; a 64 MiB output budget or a failed archive write stops the job before publication. The trace reuses the activity reducer and transcript (now producer-neutral, with Claude Code stream-json, phases and GitHub rows), streamed by `GET /api/jobs/stream` with a sequence cursor and archive-backed resync. New read-only routes `/api/jobs`, `/api/jobs/actions`, `/api/jobs/run`, `/api/jobs/events`, `/api/jobs/artifact` and the LLM log inventory `/api/logs`, `/api/logs/run`, `/api/logs/artifact`; none is exported to the static demo. `scripts/check_container.py python` takes test paths for focused runs, and a new `web` kind runs `tests/*.test.mjs` and the web controls check and build in the bounded Node worker. Tests use a real local Git fixture, a fake coding CLI and a fake GitHub; a real GitHub sandbox run is still to be authorized separately.

- Server port, PR 1: the Python web server can sit behind a trusted front. With `READER_WEB_FRONT_SECRET` set (off by default), every request must prove that secret in `X-Reader-Front-Secret` (constant-time compare, else 403) and carry the front's `X-Reader-Identity`; the client's Host and Origin, forwarded unchanged, are re-checked against that identity and the web config, writes still need the token (`READER_WEB_FRONT_TOKEN` lets the front supply it) and JSON. Without the secret the headers are ignored and behaviour is unchanged; a new contract case checks that client-sent front headers grant nothing.

- Search page under contention (#57): its passage search now waits up to 8 seconds for a running search, as content and semantic search do, instead of answering 429 at once, and the page retries any 429 on `/api/search/page` (including the server's busy gate) after 0.5, 1, 2, 4 and 8 seconds, like the Documents picker. A search that never runs shows *Search couldn't finish*, never the no-match note.

- Math typesets after first paint (fixes #117): a document with formulas is shown as soon as its place is restored, with TeX placeholders, instead of waiting for KaTeX (a synthetic 1,500-formula document became visible in about 0.27 s instead of 1.8 s, and finished typesetting sooner). Formulas near the reader go first; the first block in view stays put while heights change, in scroll and two-page mode; highlights and an open find are redrawn from the typeset text; prose colors skip formulas. `web_math.cjs` covers a math-heavy fixture with a late bookmark, a note beside math, find during typesetting and TeX copy.

- No web API answer names a host folder any more (#105), since the same answers reach allowed tailnet browsers: `/api/search` drops `absolute_path` (the MCP tools keep it), `/api/inbox` reports `codex: {name, installed}` and `/api/local-model` `server.cli: {name, installed}` instead of executable paths, and Companions paths, chat raw output, the inbox activity transcript and error messages show the vault as `<vault>` and the home folder as `~` (Set path accepts both forms). A new HTTP test walks every GET route on the synthetic fixture and fails on any host path. The static exporter's scrub no longer needs to drop `absolute_path`; its refusal check stays.

- Archive every local-model run (fixes #82): each worker batch is kept forever under `logs/llm/local-model/<date>/<run>-b<batch>/` with a request template, each item's request and response JSON, and `meta.json` (preset, base URL host only, model, prompt versions, per-item and batch outcome), sealed and committed on its own with a `Reader-Log` trailer. The API key and `Authorization` header never reach the archive (the key is scrubbed from echoed text). **Run** is refused below the 50 GiB free-disk reserve, as for chat, and a run stops before a batch it could not log. Art made by the local model also logs the provider's preset and host. Reader's own `Reader-Log` commits of `logs/llm/` are no longer attributed to a voice running at the time. Embedding requests are not archived (vectors, not text; see docs/web.md LLM logs).

- Chat: one Reader web server per vault owns chat (#20, #72). The owner holds `.reader/voice-runner/supervisor.lock` (flock, released by the kernel when it exits, plus a heartbeat record so a host and a container on one vault also see each other). A second server serves chats read-only: it never recovers turns or rewrites `state.json`, its chat actions answer 409 *Another Reader server owns chat for this vault*, and the chat panel shows that above the composer. It takes over on its next chat action once the owner stops. Recovery now rewrites `state.json` only when it changed a turn, and a server that only reads writes nothing to the vault.
