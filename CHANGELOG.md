# Changelog

## Unreleased

- Article art opens the article as a hero (#145): an article with art now opens on it, like a magazine feature. In continuous reading the art is full width at the top (at most 78% of the window), the title and byline follow, and a caption carries the Artist's note and **Begin reading ↓**; in two-page reading the art fills the whole first spread across both pages, with the title, kicker, byline and any standfirst over it and **Turn the page →**, and the text begins on the next spread (empty spacer pages keep spread math, bookmarks, jumps, find and pins correct). The hero is live where motion is allowed, else the still; the page turn paints the still frame kept under the live canvas (the rasterizer now skips WebGL art canvases and honors `object-fit: cover`). Its `/api/art` request goes out with the document's. Settings › **Open articles with their art** (on by default) turns it off; Space g hides it for the session. Articles without art are unchanged.
- First document open no longer waits on the version timeline (#116): the article renders as soon as `/api/document` (and `/api/changes`) arrive instead of racing `/api/versions` against 600 ms. A timeline that is already here joins the first layout; a slower one fills in the status twin and inserts the version chip afterwards, keeping the reader on the same block in scroll and two-page reading. New browser test `tests/web_versions_late.cjs` delays `/api/versions` by 2 s.

- Plugin live inbox check (fixes #100): `plugins/reader/tests/live/inbox.py` claims and releases through this checkout's `skills/upkeep/scripts/check.py` instead of whatever Upkeep copy is installed in the Codex home; `--installed-skill` tests the installed copy on purpose.

- Upkeep worker recommendation (fixes #3): the check reports `recommended_intake_workers`, documented as a recommended delegation count rather than a live worker count; `intake_workers` stays as a deprecated alias with the same value and is named under `deprecated`.

- Article shape stars (fixes #81): long documents keep their neighbour stars. A neighbour is dropped only when its projection has no meaningful direction (within 0.05 of the centre), not when it lies within 0.15 of any passage, a test that erased every star once the ribbon filled the sphere; the browser already draws stars at a fixed radius along their direction.

- Activity transcript headings (fixes #79): an agent message that opens with `# Title`, as the inbox runner's final report usually does, now renders its headings at transcript scale (17px, matching the Librarian's report view) instead of the page's display heading size.

- Search format 1 retired (fixes #9): `search_legacy.py`, the read-only format 1 fallback for search, the search page, Read next and article shapes, and seeding format 2 from format 1 vectors are gone, with the frozen `tests/legacy_search_v1.py`. A vault with only `.reader/search.sqlite3` is asked to rebuild ("Reader no longer reads the format 1 index"); the Behind the scenes card shows Missing and keeps the explicit Remove for the old file, which no longer needs a format 2 build first.

- Static web demo: chat works with the demo's scripted voices (#108). Sending a message appends it and a keyword-picked reply from the same `replies.json` table `reader demo` uses, exported as `data/chat.json`; mentions, two-voice answers, replies, the random pick and Wren's pasted reply behave as in the local demo. Turns stream through the chat panel's real event path (`state`, `started`, `delta`, `posted`, `done`), messages are labelled "only in this browser" and kept in `localStorage` (Reset clears them), and nothing leaves the browser. Chime-ins and raised hands still need Reader.
- Companions *Agents and models* card (#134): `claude`, `codex` and `agy` are looked up on the PATH and HOME Companions was configured with, like every other companion probe, instead of the server process's own, so the browser fixture no longer reports the host's installed CLIs. `READER_CLI_CANDIDATES` (folders separated by `:`, may be empty) replaces the usual install folders (`~/.local/bin`, `/opt/homebrew/bin`, `/usr/local/bin`) for both the card and voice CLI resolution.
- Voice turn attribution (#133): an art commit Reader makes while a voice turn runs (a commission, favorite or still, with a `Reader-Art` trailer, touching only `logs/llm/` and the `art/` folder its trailer names) is no longer listed in the turn's `commits`, and art paths only Reader's commits touched are no longer the turn's `changed_paths`. A voice commit that carries a `Reader-Art` trailer but touches other files, or another article's art folder, still counts as the voice's.
- Art commissions: one server per vault owns art (#138). The owner holds `.reader/art/supervisor.lock` (the chat supervisor's flock plus heartbeat record, so a host and a container on one vault see each other) and is the only server that recovers, runs or records art jobs; a job's `owner_pid` is for display only. A second server no longer marks the owner's running jobs failed, seals their logs or runs its queued jobs again: it shows them read-only (no Cancel; the Art studio says *Another Reader server owns art for this vault; art is read-only here.*), answers 409 for every `POST /api/art` action, and takes over on its next art action once the owner stops. `GET /api/art/jobs` adds `ownership`. New browser suite `tests/web_art_owner.cjs`.
- Theme Editor: per-level heading fonts and sizes. A new **Headings** section sets a font (Default is the Reading font; bundled and downloaded families are offered) and a size in pixels (10–120; blank keeps the stylesheet default) for each of H1–H6, and the preview shows all six levels. Themes store them as `headings: {h1…h6: {font, size}}`, validated by the server; older theme files read with every level at its default. Document headings read `--hN-font`/`--hN-size` with today's values as fallbacks, so built-in themes are unchanged. The H1 font also sets the document title; the title keeps its responsive size. Heading fonts are loaded like role fonts. `tests/test_themes.py` covers defaults, round-trip and refusals; `web_themes.cjs` sets an H1 font and an H2 size and checks the preview, the saved theme and a document.

- Find keeps the article's text projection between keystrokes (part of #35): typing in find no longer re-projects the whole article, so a later keystroke on the synthetic 2 MB benchmark takes about 2 ms instead of about 290 ms. The projection is built from typed arrays of offsets instead of per-character objects (about 85 ms instead of 300 ms when it must be rebuilt) and is dropped whenever the article's text changes (render, edition, embeds including lazy ones, late math, diagrams, code highlighting); pins and decorations keep it. Hits are unchanged; `web_perf.cjs` asserts the keystroke time, invalidation and identical ranges.

- The static web demo knows it is static (#107): Behind the scenes no longer starts a freshness check or raises "Couldn't start that job"; server-only controls (Check again and rebuilds, You got mail, theme saves, Generate art, queue writes, the chat composer) are disabled with a "Needs Reader on your computer" tooltip, and the Service, Companions and Local model sections are left out with one note. The shim's `window.readerStaticDemo` is the only signal, read through `needsReader()`; its `serves.chat` is the single switch #108 flips. A normal server is unchanged.

- Web build licenses (#88, #126): `controls/licenses/` and the `build-meta.json` dependency map now list only npm packages that contribute bytes to a shipped output (esbuild's per-output `bytesInOutput`), and the folder is rebuilt from scratch each build, so a removed dependency's license no longer lingers. 22 tree-shaken packages drop out (Shiki's HTML renderer and `hast` utilities, CodeMirror's unused HTML/CSS/JavaScript language packages, `crelt`, `reselect`, and the re-export-only `shiki` package); no bundled JS or CSS byte changes and every shipped package keeps its license.
- Reading log: a vault without `voices.json` now has no voices (#93). Reader no longer falls back to one deployment's fixed list of participant names; `Engagement.group()` takes the voice set explicitly, and a repository guard (`tests/test_no_deployment_names.py`) keeps such names out of shipped code. Vaults that relied on the old fallback should list their voices in `voices.json` (the demo already does).


- Status line: items give way by declared priority (#74). Every status item carries `data-status-priority` (1 never gives way; larger numbers go first), and one measure pass hides the lowest priorities until the line fits, so a new item can no longer push the mode or Backstage off screen; an item without a declaration gives way first. Items keep their content width, so a crowded phone line no longer crushes the mode label, and the fixed 520/400/340 px hide rules are gone. A browser check injects an extra item at 700, 390 and 320 px in both layouts.

- Scratch pad fixes (#92, #114): a `#scratch` or `#scratch=<id>` pane is kept in split layouts and survives `#split=` restore instead of falling back to the homepage, and the preview shows local images and `![[embeds]]` by resolving from the notebook folder. `/api/resolve`, `/api/resolve-batch` and `/api/embeds` accept a source folder written with a trailing slash (`from=library/notebook/`): an existing real library folder, or the notebook before its first save; path validation, symlink refusal and the 404 for a missing source document are unchanged.

- Browser suites run from a fresh clone (#14): `playwright-core` 1.64.1 is now an exact, development-only dependency in a root `package.json`/`package-lock.json`, so `npm ci` at the repository root is the only setup and `tests/web_*.cjs` resolve it without `READER_PLAYWRIGHT` (still honored as an override). It downloads no browser; the suites keep using the installed Google Chrome (`READER_CHROME` overrides). Python tests now pin this checkout's `src` (#15): `tests/conftest.py` puts its absolute path first in `sys.path` and `PYTHONPATH` and stops if `reader_mcp` resolves elsewhere, so a worktree no longer tests another checkout's code through an editable virtual environment.

- Search page under contention (#57): its passage search now waits up to 8 seconds for a running search, as content and semantic search do, instead of answering 429 at once, and the page retries any 429 on `/api/search/page` (including the server's busy gate) after 0.5, 1, 2, 4 and 8 seconds, like the Documents picker. A search that never runs shows *Search couldn't finish*, never the no-match note.

- Math typesets after first paint (fixes #117): a document with formulas is shown as soon as its place is restored, with TeX placeholders, instead of waiting for KaTeX (a synthetic 1,500-formula document became visible in about 0.27 s instead of 1.8 s, and finished typesetting sooner). Formulas near the reader go first; the first block in view stays put while heights change, in scroll and two-page mode; highlights and an open find are redrawn from the typeset text; prose colors skip formulas. `web_math.cjs` covers a math-heavy fixture with a late bookmark, a note beside math, find during typesetting and TeX copy.

- No web API answer names a host folder any more (#105), since the same answers reach allowed tailnet browsers: `/api/search` drops `absolute_path` (the MCP tools keep it), `/api/inbox` reports `codex: {name, installed}` and `/api/local-model` `server.cli: {name, installed}` instead of executable paths, and Companions paths, chat raw output, the inbox activity transcript and error messages show the vault as `<vault>` and the home folder as `~` (Set path accepts both forms). A new HTTP test walks every GET route on the synthetic fixture and fails on any host path. The static exporter's scrub no longer needs to drop `absolute_path`; its refusal check stays.

- Archive every local-model run (fixes #82): each worker batch is kept forever under `logs/llm/local-model/<date>/<run>-b<batch>/` with a request template, each item's request and response JSON, and `meta.json` (preset, base URL host only, model, prompt versions, per-item and batch outcome), sealed and committed on its own with a `Reader-Log` trailer. The API key and `Authorization` header never reach the archive (the key is scrubbed from echoed text). **Run** is refused below the 50 GiB free-disk reserve, as for chat, and a run stops before a batch it could not log. Art made by the local model also logs the provider's preset and host. Reader's own `Reader-Log` commits of `logs/llm/` are no longer attributed to a voice running at the time. Embedding requests are not archived (vectors, not text; see docs/web.md LLM logs).

- Chat: one Reader web server per vault owns chat (#20, #72). The owner holds `.reader/voice-runner/supervisor.lock` (flock, released by the kernel when it exits, plus a heartbeat record so a host and a container on one vault also see each other). A second server serves chats read-only: it never recovers turns or rewrites `state.json`, its chat actions answer 409 *Another Reader server owns chat for this vault*, and the chat panel shows that above the composer. It takes over on its next chat action once the owner stops. Recovery now rewrites `state.json` only when it changed a turn, and a server that only reads writes nothing to the vault.
