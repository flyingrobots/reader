# Changelog

## Unreleased

- Companions: Reader degrades gracefully without its optional companion projects and offers to set them up. A new **Companions** section in Behind the scenes shows AI-TTS, Colorful Language, wide-md and git-locks (installed, version, path, not found, too old, daemon not running), what each adds, its repository, and Install, Update, Start…, How to install (with Copy), Set path and Check again; an *Agents and models* card lists the `claude`, `codex` and `agy` CLIs (status only) and the GPU coordination mode. Space s without AI-TTS and Space c without Colorful now show a calm prompt naming what is missing, with Install where safe and a per-feature Don't show again, instead of an error toast. Install builds the pinned Colorful Language 0.4.0 (`61d0aa8`) (or runs `scripts/install_wide_md.py`) into `<vault>/.reader/tooling` as a background maintenance job with step progress, toasts, a bounded log, timeouts, a single-install rule and the workstation `host/heavy-work` lock when git-locks is present; Start asks AI-TTS's own launch agent after a confirmation that lists what changes. New `GET/POST /api/companions` and `GET /api/companions/log`; paths are stored in `.reader/companions.json` and can be set only from a local browser.

- Work without git-locks (fixes #95): the local model's GPU lock fell back to nothing, so every batch failed for anyone without git-locks; it now holds a Reader-local `.reader/gpu.lock` (*GPU coordination: This Reader only*) and fails closed only when git-locks is present and its store errors or a configured store is invalid. The workstation store is chosen by `READER_GIT_LOCKS_STORE`, the path set in Companions or `GIT_LOCKS_STORE`, instead of a hard-coded machine path. `scripts/reader_service.py install` and its updates no longer require git-locks (a flock serializes their Git changes). git-locks discovery is shared and injectable (`READER_GIT_LOCKS`, `READER_GIT_LOCKS_CANDIDATES`). Chat and scratch pad commit locks no longer inherit a host `GIT_LOCKS_STORE`, which put the vault's `.git/` key in the wrong store.
